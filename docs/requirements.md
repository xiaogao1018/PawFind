# PawFind — AI 社区宠物走失与智能寻回平台

> 需求规格说明书（MVP）  
> 版本：v1.0  
> 状态：需求草稿，开发前确认  
> 目标周期：8 周（每周 5 个开发日）  
> 技术方向：Vue 3 + TypeScript / Spring Boot + Java / MySQL / Spring AI + 大模型 API

## 1. 项目概述

### 1.1 项目背景

宠物走失后，主人需要快速发布信息、收集社区目击线索并核实；社区居民也需要集中查看求助信息、分享养宠经验。PawFind 为此提供统一的寻宠与社区互动平台，并通过 AI 对话辅助用户整理寻宠信息、生成启事和获取行动建议。

### 1.2 项目定位

面向社区的 **宠物走失与寻回 + 养宠互动 + 内容审核 + AI 寻宠助手** 的 Web 平台。首版优先跑通核心业务闭环，不追求复杂算法。

### 1.3 项目目标

1. 让宠物主人发布走失信息并管理线索、寻回状态。
2. 让居民发布发现宠物信息，向指定走失记录提交目击线索。
3. 让登录用户浏览、发布和评论社区养宠经验帖、求助帖。
4. 让管理员对社区帖子先审后发，持续控制内容可见性并维护秩序。
5. 让 AI 对话帮助用户整理走失情况、生成寻宠启事并提供一般建议。
6. 在 8 周内形成可部署、可演示、可测试的 AI 全栈实习项目。

### 1.4 目标用户

| 角色 | 主要需求 |
| --- | --- |
| 游客（未登录） | 浏览公开的走失与发现信息、查看基础详情 |
| 社区成员（已登录） | 发布/管理走失与发现信息、提交线索、浏览/发布/评论社区帖子、使用 AI 对话 |
| 管理员 | 管理用户、审核和隐藏/恢复帖子、管理评论及违规走失信息、查看审核操作记录 |

> 第一版采用两类登录角色：`USER` 与 `ADMIN`；游客不持有角色。

## 2. MVP 范围

### 2.1 必做功能（P0）

- 账号注册、登录、退出和用户/管理员权限隔离。
- 走失宠物信息发布、展示、编辑、标记已寻回。
- 发现宠物信息发布、展示和编辑。
- 针对走失记录提交目击线索；宠物主人查看并更新线索核实状态。
- 社区成员登录后浏览已审核且可见的帖子；发布经验帖/求助帖并查看审核结果；对公开帖子评论。
- 管理员审核社区帖子（通过/驳回）、隐藏/恢复通过审核的帖子、管理评论、管理用户和违规信息。
- AI 寻宠多轮对话：寻宠建议、信息补全和启事生成；模型异常有明确反馈。
- 图片上传、基础输入校验、访问控制、操作日志与基础部署。

### 2.2 可选增强（P1，P0 完成后再做）

- 地图展示与按地区筛选走失、发现信息。
- AI 通过受控业务接口查询公开寻宠记录（Tool Calling）。
- 简单消息通知（例如帖子审核结果、收到线索）。
- AI 视觉特征提取和候选相似记录推荐（仅推荐，人工确认）。

### 2.3 本版不做（Out of Scope）

- 自训练宠物识别模型、保证身份的自动图片识别。
- 自动寻找或联系第三方、自动发布外部平台内容。
- 复杂多 Agent、MCP 工作流平台。
- 支付、悬赏结算、原生 App/小程序。
- 复杂即时聊天、推荐算法、复杂地理轨迹预测。
- AI 自主执行管理操作、AI 自动批准或删除社区帖子。

## 3. 核心业务规则

1. 游客可以浏览公开走失与发现记录；**社区帖子仅登录成员及管理员可浏览**。
2. 发布走失、发现、线索和社区帖子，以及发表评论、使用 AI 对话，都需要登录。
3. 走失/发现记录由其发布者编辑；管理员可进行违规信息隐藏/恢复，所有操作记录留痕。
4. 用户新建社区帖子初始状态为 `PENDING`（待审核），未审核通过不得公开。
5. 帖子的**审核状态**和**展示状态**独立：`audit_status = PENDING | APPROVED | REJECTED`，`visibility_status = VISIBLE | HIDDEN`。
6. 只有 `APPROVED + VISIBLE` 的社区帖子会出现在普通用户列表、搜索及详情入口；普通作者可以在“我的帖子”查看自己待审核、驳回或隐藏的记录与原因。
7. 管理员驳回帖子需填写原因；管理员隐藏已通过帖子需填写原因，并可以恢复显示。**隐藏不能绕过审核**：只有 `APPROVED` 的帖子可恢复公开。
8. 用户编辑已审核通过的帖子正文或图片后，帖子重新进入 `PENDING`，不直接公开修改内容；MVP 可将整条帖子暂时下架待重新审核。
9. 评论仅能发布到 `APPROVED + VISIBLE` 的帖子；评论第一版发布后可见，管理员可以隐藏违规评论。
10. 宠物主人可以对自己的走失记录标记 `LOOKING`（寻找中）或 `FOUND`（已寻回）；线索状态为 `PENDING`（待核实）、`VERIFIED`（已核实）、`INVALID`（无效）。
11. 走失/发现信息涉及的电话号码和精确位置默认不公开；对外只展示适当模糊的社区/区域信息。联系信息须经本人授权后可见或通过站内方式转达。
12. AI 只能基于用户已提供的信息生成启事和建议；不得编造目击事实、承诺寻回结果或未经用户确认自行发布内容。

## 4. 详细功能需求与验收标准

### F01 用户与权限管理（P0）

**用户故事**：作为居民，我希望注册并登录，以便发布信息和使用社区功能；作为管理员，我希望管理违规账号。

**功能要求**
- 支持账号注册、登录、退出；密码采用安全哈希存储。
- 前后端区分 `USER` 和 `ADMIN`，所有敏感接口在后端校验角色及资源所有权。
- 用户可查看/修改自己的基础资料。
- 管理员可查看用户列表并禁用/恢复账号，避免已禁用账号继续登录或执行受保护操作。

**验收条件**
- [ ] 新用户可以注册、登录、退出，错误凭证有明确提示。
- [ ] 未登录访问发帖/线索/AI 接口被拒绝。
- [ ] 普通用户访问管理员接口被拒绝。
- [ ] 普通用户无法修改其他人的资源。
- [ ] 管理员可禁用用户，禁用后该用户无法继续使用受保护功能。

### F02 走失宠物信息（P0）

**用户故事**：作为宠物主人，我希望上传照片并发布走失地点、时间与特征，方便附近居民提供线索。

**功能要求**
- 新增、列表、详情、编辑自己的走失信息。
- 字段：宠物名称（可未知）、种类、特征描述、至少一张照片、走失日期时间、区域/大致地点、当前状态、补充说明。
- 走失状态：`LOOKING | FOUND`；列表默认可按最近发布时间排序及按状态筛选。
- 发布者可标记已寻回；管理员可隐藏/恢复违规走失记录。

**验收条件**
- [ ] 登录用户填写必要信息并上传图片后发布成功，信息在公开列表可见。
- [ ] 缺少必要字段、非法图片格式或超限文件时无法提交并给出提示。
- [ ] 发布者可编辑自己的记录并标记为“已寻回”。
- [ ] 其他普通用户不能编辑该记录。
- [ ] 管理员隐藏的记录不会出现在公开列表/详情入口。

### F03 发现宠物上报（P0）

**用户故事**：作为居民，我希望上报看到的疑似走失宠物，让主人有机会检索到相关记录。

**功能要求**
- 新增、列表、详情和编辑自己的发现记录。
- 字段：宠物种类（可选/未知）、特征描述、照片、发现时间、发现区域/大致地点、补充说明。
- 不强制填写品种与宠物名称。
- 管理员可以隐藏不合规信息。

**验收条件**
- [ ] 不知道具体品种也能完成发现上报。
- [ ] 发现记录可被检索与查看。
- [ ] 只有发布者可修改自己的记录，管理员可处理违规信息。

### F04 目击线索管理（P0）

**用户故事**：作为社区成员，我希望向一条走失记录提供目击线索；作为主人，我希望查看和核实这些线索。

**功能要求**
- 线索必须关联一条有效走失记录。
- 线索内容包括目击时间、地点描述、文字信息，照片可选。
- 仅对应走失记录发布者和管理员可查看完整线索详情；线索提供者可以查看自己提交的内容。
- 走失记录发布者可以设置 `PENDING | VERIFIED | INVALID` 并添加备注。

**验收条件**
- [ ] 已登录成员可对寻找中的走失记录提交线索。
- [ ] 无关联记录或必填字段缺失时提交失败。
- [ ] 主人可查看收到的线索并修改核实状态。
- [ ] 无关用户无法查看完整的非公开线索详情。

### F05 社区互动（P0）

**用户故事**：作为登录社区成员，我希望分享养宠经验或发布求助帖、浏览他人帖子并评论交流。

**功能要求**
- 帖子分类：`EXPERIENCE`（经验分享）、`HELP`（求助）。
- 帖子包含标题、正文、可选图片、作者、创建时间、审核状态和显示状态。
- 登录成员可以创建帖子、查看“我的帖子”和审核结果、编辑自己的帖子。
- 只有审核通过且可见的帖子才能被社区成员浏览和评论。
- 评论支持添加、列表查看；评论作者可删除自己的评论，管理员可隐藏违规评论。第一版不做楼中楼。

**验收条件**
- [ ] 登录成员可提交帖子，提交后状态为“待审核”，其他普通用户不可见。
- [ ] 管理员审核通过后，且显示状态为可见，帖子才出现在社区列表。
- [ ] 审核驳回时作者能看到驳回原因。
- [ ] 用户编辑已公开帖后，修改内容必须重新审核才能公开。
- [ ] 审核中、驳回或隐藏的帖子不能通过直接访问公开详情接口绕过限制。
- [ ] 仅公开帖可以评论，违规评论可由管理员隐藏。

### F06 管理员后台（P0）

**用户故事**：作为管理员，我希望审核、隐藏和恢复社区内容，处理违规用户与信息，维护社区秩序。

**功能要求**
- 管理员独立入口与后台页面，复用同一个 Vue 项目或独立路由分区。
- 审核队列：待审核列表、帖子详情、通过/驳回（带理由）。
- 内容管理：按审核状态与显示状态筛选帖子；隐藏/恢复已通过帖子；隐藏违规评论。
- 用户管理：查看用户、禁用/恢复账号。
- 走失/发现信息管理：查看列表并隐藏/恢复违规记录。
- 审计日志：记录管理员 ID、操作对象、动作、原因和时间。

**验收条件**
- [ ] 普通账号无法进入后台或调用后台接口。
- [ ] 新帖子进入待审核列表，未通过不会出现在公开列表。
- [ ] 审核通过后帖子可展示；驳回后记录审核原因。
- [ ] 管理员可以隐藏已通过的帖子，公开访问立即失效。
- [ ] 隐藏的已通过帖子可恢复；未通过审核的帖子无法被直接恢复公开。
- [ ] 管理员可以隐藏违规评论和管理违规走失/发现信息。
- [ ] 每次审核和内容管理操作均可查询对应日志。

### F07 AI 寻宠对话助手（P0）

**用户故事**：作为寻找宠物的主人，我希望通过对话获得寻宠建议，并把零散信息整理成发布用启事；作为养宠成员，我希望得到一般性养宠信息，但知道 AI 回复不能替代专业意见。

**功能要求**
- 登录成员可进入 AI 聊天页面，进行多轮对话。
- 基于 Spring AI 调用大模型，支持正常显示回复；建议采用 SSE 流式输出。
- 场景 A：根据宠物种类、走失时间地点、宠物习性生成分步骤寻找建议。
- 场景 B：根据用户描述，整理宠物特征与走失时间地点，缺失信息时追问。
- 场景 C：生成可复制的寻宠启事草稿，用户人工确认后再手动发布。
- 场景 D：回答一般性养宠问题；高风险健康问题提示咨询兽医。
- 提供基本的聊天上下文管理；模型超时、额度不足或服务异常时明确提示。
- 首版不允许 AI 自行调用管理员操作，不对未经核实的线索做事实性断言。

**验收条件**
- [ ] 登录成员能够发送消息并收到正常回复，支持连续追问。
- [ ] 对于缺失的走失信息，AI 能询问或明确标注未知，不随意编造。
- [ ] AI 能依据用户输入生成结构化、可复制的寻宠启事草稿。
- [ ] 生成启事不会自动公开发布。
- [ ] AI 调用失败时有错误提示，页面不会卡死或暴露密钥。
- [ ] 大模型 API Key 只保存在服务端配置中，不写入前端代码。

## 6. 关键状态与业务流程

### 6.1 宠物寻回闭环

`主人发布走失信息 → 居民浏览并提交目击线索 / 发布发现记录 → 主人查看和核实线索 → 线下自行确认 → 主人标记已寻回`

- “发现上报”与“走失信息”首版是两类独立记录，不做自动强制关联。
- 系统辅助交换线索，不保证成功寻回；线下接触须注意安全。

### 6.2 社区帖子审核流程

`用户提交帖子 → PENDING（不可公开） → 管理员审核`

- `APPROVED + VISIBLE`：对登录社区成员公开，可评论。
- `REJECTED`：不公开；向作者展示原因。
- `APPROVED + HIDDEN`：管理员主动隐藏，不公开；记录原因。
- `APPROVED + HIDDEN → APPROVED + VISIBLE`：管理员恢复展示。
- `已通过帖子内容发生修改 → PENDING`：重新审核，修改后内容不得直接公开。

**技术约束**：`audit_status` 表示审核结果；`visibility_status` 表示公开控制。后端查询公开数据时必须同时校验二者。

## 7. 非功能性需求

### 7.1 安全与隐私

- 使用安全的密码哈希与认证机制；接口验证身份、角色和资源所有权。
- 上传图片校验类型与大小；限制文件访问、过滤不可信输入。
- 对联系方式和目击位置做最小化展示，默认不公开精确住址/电话。
- 不在代码仓库中提交密码、数据库凭据或大模型 API Key。
- 管理员操作记录可追踪；重要操作有明确二次确认。

### 7.2 可用性

- 页面支持常见桌面浏览器，基础移动端适配。
- 列表分页，表单有校验与错误提示。
- AI 响应较慢时显示加载/流式状态，失败后可重试。
- 核心业务功能与 AI 服务解耦：AI 服务不可用时仍可发布走失信息和线索。

### 7.3 可测试和可交付

- 核心接口有基础自动化或手工测试记录。
- 可通过配置文件或环境变量在本地启动，并具备 README 部署说明。
- 提供测试普通用户和管理员账号的初始化方式（不得在生产环境使用固定弱密码）。

| W8 | Bug 修复、界面优化、README、演示脚本、简历总结 | 完整演示：走失寻回 + 社区审核 + AI 对话 |

> 每周计划按 5 个开发日安排，实际遇到技术阻碍时优先保证 P0 质量，不为增加技术名词而堆叠功能。

## 9. MVP 最终验收场景（端到端）

1. **寻宠场景**：普通用户注册登录 → 发布走失记录 → 第二个用户查看并提交线索 → 原发布者查看、核实线索 → 标记宠物已寻回。
2. **社区场景**：用户登录 → 发布经验帖 → 审核前其他用户看不到 → 管理员通过 → 社区成员浏览和评论 → 管理员隐藏 → 社区成员无法再查看 → 管理员恢复展示。
3. **驳回场景**：用户提交求助帖 → 管理员驳回并填写原因 → 用户在“我的帖子”看到原因 → 修改后重新提交审核。
4. **权限场景**：游客无法发布或查看社区；普通用户无法调用管理员接口或编辑其他人的数据。
5. **AI 场景**：用户输入“我家猫昨天晚上在小区附近走失” → AI 追问缺失的特征与具体区域 → 生成可复制的寻宠启事草稿 → 用户自行确认发布。
6. **故障场景**：大模型 API 失败时提示错误，走失信息发布和社区浏览仍正常工作。

## 10. 待确认事项

本草稿暂按以下默认规则设计，开发前可调整：

- 社区帖子只对登录成员可见；公开走失/发现信息允许游客查看。
- 社区帖子需审核，评论采用先展示、管理员事后治理。
- 社区帖子允许图片；第一版暂不做点赞、收藏、关注和私信。
- 用户联系方式默认隐藏；第一版通过平台线索和授权联系机制处理。
- AI 对话先做建议、信息整理、启事生成；暂不做自动工具调用。
- 地图与 AI 图片匹配作为 P1，若 8 周进度充足再添加。
